# Roadmap проекта Expenses

План разработки по **срезам**. Срез = тонкая сквозная функциональность, которая уже работает. Наращиваем слоями, не строим всё сразу.

Формат работы — см. [../CLAUDE.md](../CLAUDE.md). Изначально был гибрид (логику писал пользователь); с 2026-07-18 для этого проекта **весь код пишет Claude**, пользователь изучает результат и тестирует после деплоя. Ранние срезы (0–1) делались в старом формате.

Легенда: ✅ сделано · 🟨 в процессе · ⬜ не начато.

## Срез 0 — «шагающий скелет»
Цель: убедиться, что весь путь `домен → nginx → сертификат → Ktor` живой, ещё без бизнес-логики.

### 0а. Локальный каркас — ✅ СДЕЛАНО (2026-07-15, делал Claude)
- ✅ `backend/` — самостоятельный Gradle-проект на Ktor 3.0.3 (Kotlin 2.1.0), wrapper Gradle 8.14.3.
- ✅ Эндпоинт `GET /health` отвечает `{"status":"ok"}`.
- ✅ Сервер слушает `127.0.0.1:8080` (наружу отдаёт nginx).
- ✅ Собрано (`BUILD SUCCESSFUL`) и **проверено запуском** фэт-джара: `HTTP 200 {"status":"ok"}`.
- ✅ Репозиторий создан и запушен: https://github.com/vihrea1337/expenses (private). Коммиты: каркас + `.gitattributes` (единые переносы строк, чтобы `gradlew` работал на Linux).

Как проверить локально:
```powershell
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
cd C:\Users\main\Desktop\GitArea\Expenses\backend
.\gradlew.bat run
# затем открыть http://127.0.0.1:8080/health ; остановить — Ctrl+C
```

### 0б. Деплой на VPS — ✅ СДЕЛАНО (2026-07-16)
`https://sashlevhealth.duckdns.org/health` отвечает `{"status":"ok"}` снаружи. Выполнено:
- ✅ Java 21 (`openjdk-21-jre-headless`) на хосте VPS.
- ✅ Фэт-джар (`buildFatJar` → `expenses-backend-all.jar`) залит через **scp** в `/opt/expenses/`.
- ✅ Поддомен добавлен в существующий nginx — **один** `server`-блок (`127.0.0.1:8081 ssl`, `proxy_pass http://127.0.0.1:8080`). VPN и сайт не тронуты.
- ✅ Сертификат Let's Encrypt через `certbot certonly --webroot` (+ автопродление `certbot.timer`, deploy-hook перезагружает nginx).
- ✅ systemd-юнит `expenses-backend.service` (User=expenses, Restart=on-failure) — работает круглосуточно, слушает `127.0.0.1:8080`.

Как реально устроен VPS (важно для будущих правок) — см. [deploy.md](deploy.md).

## Срез 1 — одна трата end-to-end — ✅ СДЕЛАНО
Цель достигнута: трата, введённая в боте, видна в приложении и на сайте, и наоборот.

- ✅ Таблица `expenses` в PostgreSQL (через Exposed): id (UUID), сумма, категория, заметка, дата.
- ✅ `POST /api/expenses` — добавить трату; `GET /api/expenses` — список.
- ✅ Telegram-бот: принимает «кофе 200», разбирает на категорию+сумму, пишет в БД, отвечает в чат.
  **Через long-polling** (не webhook — webhook отложен в бэклог, см. ниже).
- ✅ Android-экран: список трат + форма добавления (Retrofit-клиент к API).

## Бэклог — по желанию
- ⬜ **Webhook** вместо long-polling (эффективнее; требует правки nginx на VPS).
- ⬜ **Офлайн-first** в приложении (Room) + синхронизация. _Не начато сознательно (2026-09-02):
  честная реализация тянет за собой конфликт-резолюшн при синхронизации, а это отдельная
  большая задача, а не довесок к другим трём пунктам бэклога. Следующий шаг, когда до
  него дойдём: локальный Room-кэш трат, читаем из него офлайн, шлём несинхронизированные
  записи по восстановлению сети (те же id из идемпотентности ниже это уже поддерживают)._
- 🟨 **Бэкапы БД** — инструкция и cron-скрипт готовы ([backup.md](backup.md)); осталось включить на VPS.
- ✅ **Идемпотентность** (2026-09-02): клиент (Android-приложение и веб-страница) сам генерирует
  UUID трате до отправки; повторная отправка с тем же id не создаёт дубль — сервер возвращает уже
  сохранённую запись (`ExpenseRepository.add`, тесты в `DbRepositoryTest`, контрактные тесты в
  `shared/ApiContractTest`). Проверено и юнит-тестами, и живым HTTP-запросом к реальному Postgres.
- ✅ **Общий Kotlin-модуль моделей** (2026-09-02): DTO трат/бюджета/аккаунта вынесены в
  `shared/` (по образцу devlog) — один контракт на бэкенд и Android, оба подключают через
  `includeBuild`. Веб-страница как разбирала JSON руками на чистом JS, так и продолжает —
  осознанно не переведена (нет сборки на клиенте).
- ✅ **Hover на секторах диаграммы** (2026-09-02): наведение на кольцевую диаграмму по
  категориям показывает всплывающую подсказку с категорией, суммой и долей (считаем угол
  курсора от центра и сравниваем с границами долей — у conic-gradient нет отдельных
  DOM-элементов на сектор, поэтому обычный `title` не подходит). **Не проверено вживую в
  браузере** — эта сессия работала без доступа к браузеру/дисплею, только по коду и
  геометрии; проверить визуально при следующей живой сессии.
