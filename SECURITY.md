# Безопасность Expenses

Коротко и честно: как устроен доступ, где лежат секреты, что уходит наружу и какие
у проекта известные слабые места. Подробности архитектуры — в [`docs/architecture.md`](docs/architecture.md).

## Как сообщить об уязвимости

Через GitHub: вкладка **Security → Report a vulnerability** (приватное сообщение автору), либо лично
автору ([github.com/vihrea1337](https://github.com/vihrea1337)).
Просьба не публиковать подробности, пока исправление не выкачено.

## Доступ и аккаунты

- **Токен = аккаунт.** При регистрации сервер выдаёт случайный токен; клиенты отправляют его
  в каждом запросе в заголовке `Authorization: Bearer <токен>` (ktor-server-auth, `bearer`).
  Без верного токена все `/api/*`, кроме `/api/register`, отвечают `401`.
- **Изоляция пользователей.** Каждый запрос к трате фильтруется по `user_id` владельца токена —
  чужие траты нельзя ни прочитать, ни изменить, ни удалить (покрыто интеграционными тестами
  репозиториев на H2).
- **Telegram-бот** определяет пользователя по Telegram ID; связь с аккаунтом приложения —
  командой `/link <токен>`.

## Транспорт

- Вся связь клиентов с сервером — **HTTPS** (Let's Encrypt, Caddy). Бэкенд (Ktor) и Postgres
  наружу не открыты: они в отдельной docker-сети, порт наружу один — 34443 у Caddy.
- Бот работает через long-polling: сервер сам ходит в Telegram, входящих подключений боту не нужно.

## Секреты

- В git **не попадают**: `backend/secrets.properties` (локальная разработка), на сервере —
  `/opt/expenses/.env` и `/opt/expenses/expenses.env` (права `600`). Шаблоны без значений —
  `deploy/expenses.env.example`, `deploy/server/.env.example`.
- Секреты: токен Telegram-бота, ключ Groq, пароль базы, токен DuckDNS (для сертификата).

## Что уходит третьим сторонам

- **Groq** (ИИ-категоризация) получает только текст описания траты — без суммы, заметки,
  имени и токена. Без `GROQ_API_KEY` функция просто выключена.
- **Telegram** — сообщения, которые пользователь сам пишет боту.

Для пользователей это же изложено на странице [`/privacy.html`](backend/src/main/resources/static/privacy.html).

## Известные слабые места (осознанно, для pet-проекта)

- **Токен нельзя восстановить или сменить.** Нет почты/пароля — утерянный токен = утерянный
  аккаунт; утёкший токен даёт полный доступ к тратам, пока аккаунт не удалят вручную.
- **Токены в базе хранятся открытым текстом**, а не хэшем. Утечка базы = утечка токенов.
  Исправление: хранить SHA-256 токена и сравнивать хэши.
- **Нет ограничения частоты запросов** (rate limiting) — перебор токенов теоретически возможен,
  хотя при токене-UUID (122 случайных бита) практически бесполезен.
- **Регистрация открыта всем** — любой может завести аккаунт.
- **Резервные копии базы** на текущем сервере не настроены автоматически (инструкция —
  [`docs/backup.md`](docs/backup.md)).
- **APK подписан debug-ключом** и раздаётся с сайта, не через Google Play.
